# Public agent-skills starter pack: research and gap analysis

This study records the earlier research baseline. The newer [selection report](../../../../docs/skill-selection-report.md) and discipline indexes extend it with a broader set of candidates.

**Research date:** 2026-10-30. **Decision:** extend the reference library around real tasks and disciplines, using selected public upstream skills. Do not create a new skill when an adequate upstream one exists, and do not install or copy whole collections as a default.

**Conclusion:** the current library is a useful engineering and tool baseline, but it is not yet a broad starter pack. The most valuable next additions are security, product and UX, operations/reliability, quality and accessibility, research, documentation, and data/AI evaluation. Start by exposing specific skills already present in selected upstream collections, then add distinct sources only where they add useful coverage. Personal learning, data work and non-software disciplines remain genuine open research areas.

**Evidence boundary:** findings describe upstream documentation and this repository's inspected contents, not independently verified behavior, quality, security, compatibility or business impact. Confidence is medium for documented scope and low for comparative performance. None of these candidate skills was installed or run for this study. Branch links can change; review the exact current revision and license before adoption.

## Scope and method

The user clarified that the intended outcome is a broad library of public skills. Conventional [InnerSource](https://innersourcecommons.org/learn/learning-path/introduction/08/) describes company-internal collaboration; it is not the primary research objective here. This study focuses on discoverable public skills, with enough contribution guidance to keep the library maintainable. It excludes creating skills, installing integrations, assessing private company processes and ranking vendors by stars.

We inspected the current catalog, selection guide, contribution policy and validation script. We searched for public skill collections, methodology workflows, readiness assessments, discipline-specific skills, licensing and conflicting requirements, then opened primary upstream pages. Search results suggested candidates, but primary pages are cited for documented claims. The short list favors clear use cases, traceable ownership, scope and documented limitations; these are editorial judgments, not proof of superiority.

## Current-state assessment

**Observed:** this repository navigates architecture, development, research and personal development, plus five tool categories. Its development index references Matt Pocock, Addy Osmani, OpenSpec, Agent Skills and a readiness assessment. [Research](../README.md) and [personal development](../../personal-development/README.md) currently contain broad guidance rather than a strong selection of individually linked public skills. The [selection guide](../../../../docs/selection-guide.md) covers work definition, test-first work, architecture, research, handover and orchestration.

**Inference:** the missing piece is not a larger undifferentiated list: a reader needs a path from a role or problem to a specific skill, evidence of suitability, a competing option and limitations. A workflow can be well covered within an existing collection while still hard to discover because the catalog lists only its parent repository.

## Methodology and conflict choices

1. **Specification:** use the existing short [work definition](../../../../define-work/SKILL.md) for a bounded task; [Addy's spec skill](https://github.com/addyosmani/agent-skills/blob/main/skills/spec-driven-development/SKILL.md), [OpenSpec](../../development/openspec.md), or [Spec Kit](https://github.com/github/spec-kit) when a durable or structured specification provides value. Select one primary source of truth. These are not interchangeable formats.
2. **TDD:** [Matt's TDD skill](https://github.com/mattpocock/skills/blob/main/skills/engineering/tdd/SKILL.md) requires agreed seams and locates refactoring in review; [Addy's TDD skill](https://github.com/addyosmani/agent-skills/blob/main/skills/test-driven-development/SKILL.md) describes red-green-refactor. [Superpowers](https://github.com/obra/superpowers) describes TDD as an always-on philosophy. Select the practice and instructions appropriate to the request; do not silently apply incompatible sequences or mandatory approval steps.
3. **Research:** Matt's research workflow, AI4S's scientific workflow and a direct primary-source search serve different scales. Choose by output and domain, not by how many citations a tool can generate. Verify cited sources and distinguish evidence from inference.
4. **Review:** distinguish behavioral verification, general review, threat modeling, specialized security audit and accessibility review. One cannot be treated as proof of another. Appropriate human expertise remains necessary.
5. **Orchestration:** FirstMate, OmO and Superpowers have different execution models. No skill can grant delegation, create worktrees or approve publishing against the user's instructions or the harness's actual authority.
6. **Readiness:** a repository scan is distinct from a skill security review and from model or harness capability. Report exactly what was observed; a score does not establish overall readiness.

## Recommended next increments

1. Improve discovery inside the existing collections: link explicit skill paths, triggers, outputs and skip conditions for SDD, TDD, debugging, architecture, research, review, docs and delivery. Keep one canonical catalog entry per upstream and cross-link it.
2. Add narrowly scoped security, web UX/accessibility and operations indexes with one or two source-reviewed candidates each; keep model, platform, license and side-effect uncertainty explicit.
3. Evaluate candidates on representative tasks with agreed acceptance, triggering and negative-trigger cases. Capture exact versions, harness, permissions, results, costs, conflicts and failures; compare with a no-skill baseline.
4. Research public candidates for data analysis, AI evaluation, product discovery, non-web accessibility, learning and communication. Reject or defer unclear ownership, unknown permissions, poor fit or restrictive terms.
5. Only promote a candidate after checking focused skill instructions, required dependencies, license and behavior in an authorized environment. Do not equate documentation or popularity with local validation. Keep external changes, installation and release separate from this research.
